# Qwen3.8 120B day-0 readiness

Date: 2026-08-26  
Owner/host: Vector / M3 Ultra Studio, 256 GB  
Status: NO-GO for same-day Rapid/MLX support; architecture port required

## Release-time architecture audit (13:32Z)

The published checkpoint is `Qwen/Qwen3.8-Flash-Next` at immutable revision
`f5d08274bafd880402bd16f5e3e6c514136ec06c`. It is not the anticipated
Qwen3.5-compatible 120B variant:

- `architectures=["Qwen4ExpForConditionalGeneration"]`
- `model_type=qwen4_exp`, with nested `qwen4_exp_text`
- 48 hybrid layers in a 3 linear-attention : 1 full-attention schedule
- Qwen Sparse Attention (QSA) on the full-attention layers, including a learned
  indexer and separate index/cache state
- four-way gated residual streams (`hc_count=4`)
- a 51B-parameter n-gram Per-Layer Embedding (PLE) table at layer 2, including
  convolution and token-history state
- 512 routed experts, 10 active experts plus one shared expert
- one MTP layer that consumes the multi-stream hidden state and shares the QSA
  index selection contract

Neither MLX-LM main (`74e7cf931e84`) nor MLX-VLM main (`2b31570bdee8`) had a
`qwen4_exp` implementation, registry entry, or active support PR at audit time.
The primary server precedents both had same-day, still-open support changes:
vLLM PR 53896 (`d4d0f73e`) and SGLang PR 36497 (`73a25520`). Both introduce a
new model implementation plus QSA/indexer state, hyperconnection/PLE state,
cache/scheduler work, MoE handling, and an architecture-specific MTP path.
Transformers PR 48337 is the available correctness reference, not an MLX
runtime implementation.

Rapid can reuse its metadata-driven hybrid admission, Gated DeltaNet building
blocks, MoE primitives, and tokenizer-template parser selection. It cannot
reuse the Qwen3.5 model or MTP sidecar as the model implementation: doing so
would omit QSA, PLE, gated residuals, and their cache/state semantics while
loading an incompatible weight graph. A model-type alias or dense-attention
fallback is therefore explicitly rejected.

Published weight totals are 360,000,192,888 bytes for BF16 and 185,523,317,458
bytes for the FP8 twin. A generic q4/group-64 4.5-bit floor is about 101 GB,
but this is not yet a conversion promise: the 51B PLE embedding requires an
explicit quantized or offloaded MLX representation and the current generic
converter has no model class to instantiate.

Estimate after scope authorization:

- If upstream MLX lands a correct text model: 1–2 days for Rapid integration,
  conversion, and cache contracts, then 1–2 days for full-panel, performance,
  and MTP validation.
- If Rapid owns the MLX port: 6–10 engineer-days for a correct and efficient
  text implementation, conversion, QSA/PLE/cache/MTP validation; vision is a
  separate 2–4 day follow-up.

No model weights were downloaded and no conversion or publication was started.
The existing audit gate correctly rejects this new architecture.

## Architecture readiness

The released Qwen3.8-27B config is the nearest family contract:

- `Qwen3_5ForConditionalGeneration`, `model_type=qwen3_5`
- 64 decoder layers in a 3 linear-attention : 1 full-attention pattern
- GatedDeltaNet recurrent state, 262,144-token context
- one MTP layer (`mtp_num_hidden_layers=1`)
- native vision tower plus language backbone

MLX-LM 0.31.3 contains both `qwen3_5` and `qwen3_5_moe`. The shared text
implementation accepts the hybrid layer geometry, optional MoE fields, and
creates recurrent `ArraysCache` entries beside full-attention `KVCache`
entries. Its regular converter intentionally strips `mtp.*`; Rapid's existing
`scripts/extract_mtp_weights.py` restores a quantized MTP sidecar and handles
both dense and fused-MoE expert layouts. This established conversion path is
used by the day-0 script rather than a new converter.

Rapid's current contracts already cover:

- metadata-driven `qwen3_5_moe` and linear-attention detection;
- the bounded hybrid prefix-cache default;
- Qwen3 reasoning parsing;
- template-derived tool parser selection, with the alias parser chosen only
  after inspecting the released tokenizer template;
- chain MTP when a real sidecar validates against the published config.

Release-time fail-closed checks:

1. Architecture must be `Qwen3_5ForConditionalGeneration` or
   `Qwen3_5MoeForConditionalGeneration` and model type must be `qwen3_5` or
   `qwen3_5_moe`.
2. The config must declare linear/recurrent layers and at most the currently
   supported single MTP layer. A new architecture, cache geometry, or multi-MTP
   topology blocks day-0 support and requires a scoped engine change.
3. The tokenizer chat template determines the tool parser. Do not infer it
   from the model name.
4. Base generation must pass before MTP is enabled; MTP needs a non-zero
   acceptance rate and output-equivalence checks before being placed in the
   alias.

### Private precedent check

vLLM and SGLang route the released Qwen3.8 family through their hybrid cache
and Qwen parser contracts based on checkpoint metadata; neither needs a
model-name admission special case. Their public recipes use the Qwen reasoning
parser and a Qwen-family tool parser, while the exact tool grammar remains a
tokenizer-template property. MLX-LM/MLX-VLM provide the Apple-Silicon model
implementation and conversion constraints. Rapid adopts the same
metadata-first admission and deliberately diverges by keeping its existing
bounded eight-entry recurrent prefix reuse and by shipping MTP as a validated
sidecar because the upstream MLX converter removes those weights.

## Memory plan

Until real files exist, these are planning bounds, not measurements. For 120B
parameters, affine q4/group-64 has a 4.5-bit theoretical weight floor of 67.5
GB before non-quantized tensors, MTP, runtime buffers, recurrent state, and
Metal working memory.

| Quant | Planning checkpoint size | Planning peak | 256 GB Studio | 128 GB Mac |
| --- | ---: | ---: | --- | --- |
| q8 | 122–130 GB | 140–165 GB | Validation/preservation build only | Do not recommend |
| q4 g64 | 68–76 GB | 82–100 GB | Primary day-0 build | Recommended tier if real peak stays under the existing 96 GB budget |
| q3 g64 | 48–56 GB | 62–78 GB | Quality comparison only | Optional only after the full panel shows no material regression |
| q2 g64 | 34–43 GB | 48–65 GB | Research only | No recommendation; quality risk is too high for a flagship alias |

The mini is out of scope. The Desktop catalog should initially recommend q4
only to 128 GB and 256 GB systems, keep q8 Studio-only, and expose q3 only if
the correctness panel supports it. Replace these bounds with three-run peak
measurements before changing the catalog.

## Day-0 runbook

Use a fresh venv with the release candidate's pinned MLX stack. The workflow
script is stage-gated so audit, conversion, publication, mirroring, and serving
cannot be conflated accidentally.

```bash
export SOURCE_REPO='Qwen/<published-120B-repo>'
export SOURCE_REVISION='<immutable-HF-commit>'
export WORK_DIR='/Volumes/FastScratch/qwen38-120b-day0'
export Q4_REPO='mlx-community/<published-name>-4bit'
export Q8_REPO='mlx-community/<published-name>-8bit'

scripts/qwen38_120b_day0.sh audit
scripts/qwen38_120b_day0.sh download
scripts/qwen38_120b_day0.sh convert-q4
scripts/qwen38_120b_day0.sh convert-q8       # time permitting
scripts/qwen38_120b_day0.sh validate-q4

# Publication and R2 are explicit write stages.
PUBLISH_WRITE=YES scripts/qwen38_120b_day0.sh publish-q4
MIRROR_WRITE=YES scripts/qwen38_120b_day0.sh mirror-q4

scripts/qwen38_120b_day0.sh alias-candidate
scripts/qwen38_120b_day0.sh serve-q4

# In a second terminal, run the exact 20-case panel into $WORK_DIR/panel.jsonl.
MODEL_NAME='<served-model-id>' scripts/qwen38_120b_day0.sh panel
```

Then run the fixed Whittle phase-1 20-prompt panel unchanged: four reasoning,
four code, four tool-JSON, four Chinese, and four deterministic 19.3K recall
prompts. Score exact contracts and record every failure, not aggregate vibes.
Use the existing benchmark command in a fresh process for three-run TTFT,
prefill, decode, and peak-memory evidence:

```bash
rapid-mlx bench "$WORK_DIR/q4" --num-prompts 3 --max-tokens 256 \
  --max-num-seqs 1 --long-prompt-tokens 1024
rapid-mlx bench "$WORK_DIR/q4" --num-prompts 3 --max-tokens 256 \
  --max-num-seqs 1 --long-prompt-tokens 4096
```

Required artifacts are the immutable source revision, converter versions,
output file hashes, alias candidate, 20-prompt outputs/scores, three raw runs,
median TTFT/prefill/decode, and `phys_footprint` peak. Do not publish an alias
until base q4 passes, tool/reasoning framing is correct, long recall is intact,
and memory stays inside the target tier.
