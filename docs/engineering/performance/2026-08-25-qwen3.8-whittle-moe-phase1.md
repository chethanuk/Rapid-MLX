# Qwen3.8 Whittle-MoE phase-1 evaluation

## Decision

**No-go for a Rapid-MLX catalog alias or recommended-model slot in its current
v2.1 form.** The checkpoint is technically loadable without engine changes and
is viable on a 32 GB Mac, but it does not deliver the expected end-user trade:

- the fixed panel passed 10/20 cases versus 16/20 for the dense parent;
- it produced material regressions in elementary reasoning, code completion,
  and Chinese, including repetition and word-salad failures;
- median 8K-prompt TTFT improved 28.7%, but median decode throughput regressed
  35.9%, leaving 256-token end-to-end latency only 3.9% better;
- its 15.192 GB artifact is only 6.9% smaller than the 16.320 GB production
  dense checkpoint because routed experts reduce active compute, not resident
  weights.

The model remains usable as an explicitly selected experimental local path.
Re-evaluate only after a new upstream checkpoint demonstrates that the observed
reasoning, language, and completion regressions have been repaired. No Rapid
engine, alias, catalog, or release-note change is justified by this phase.

## Scope

This phase answers three questions:

1. Can current Rapid-MLX and its MLX-LM dependency load the architecture?
2. Does the whittled checkpoint preserve enough of the dense parent's behavior
   on a fixed 20-prompt panel?
3. Does the active-parameter reduction improve TTFT or decode speed on Studio?

It does not change the engine, add an alias, propose release text, or claim a
broad benchmark result.

### Reference-first check

The private architecture review checked vLLM and SGLang first. Both recognize
the causal Qwen3.5-MoE architecture as a first-class text model and normalize
the text configuration before constructing the model; neither requires a
model-name heuristic for a derivative that preserves the architecture contract.
SGLang also keeps the direct causal class distinct from the multimodal wrapper.

The MLX-native check then verified MLX-LM 0.31.3's
`models/qwen3_5_moe.py`. Its `ModelArgs.from_dict` intentionally accepts either
a nested `text_config` or a root text-only config, and its sanitization maps the
causal weight layout into the shared Qwen3.5 language model. This is exactly the
shape used by the candidate conversion.

Adopted conclusion: use normal architecture/config dispatch and the existing
text serving lane. Rejected: an architecture shim, repository-name special
case, custom model class, or conversion rewrite. Rapid's automatic lane loaded
the local checkpoint as text-only, detected `is_hybrid=True`, installed the
existing MoE/GDN fusions, applied the bounded hybrid-cache default, warmed up,
and served requests successfully.

The raw repository ID does not carry Rapid's parser profile. To isolate model
behavior from alias metadata, both arms were explicitly served with the same
`hermes` tool parser and `qwen3` reasoning parser. A future alias could express
those existing settings; it would not require a new mechanism.

## Memory feasibility

The candidate's direct MLX-LM short generation reported 15.738 GB peak MLX
memory. Rapid's warmed batched server reached 17.5 GB during the short panel.
The 19.3K-token recall panel completed, but bounded hybrid prefix snapshots add
material working-set pressure beyond the resident weights.

| Physical memory | Assessment |
| --- | --- |
| 24 GB | Marginal; not a safe recommendation. The observed 17.5 GB short-run peak nearly consumes Rapid's normal 75% application budget (18 GB) before Desktop and other applications have useful headroom. |
| 32 GB | Viable for one model and normal local use. The 24 GB application budget leaves roughly 6.5 GB over the observed short-run peak, though large retained prefixes reduce that margin. |

This checkpoint is not a memory substitute for a genuinely smaller model. Its
MoE transformation preserves almost all total parameters, so the disk and
resident-weight savings versus dense 27B are only about 1.13 GB.

## Correctness method

Both models used the same Rapid text lane, tool/reasoning parsers, temperature
zero, concurrency one, and request envelopes. MTP was not enabled. Ordinary,
code, and Chinese requests were capped at 384 completion tokens; tool requests
at 256; recall requests at 128. A case passed only if it returned the correct
answer and obeyed the requested structure without material degeneration.
Truncated but directionally correct work is recorded as partial and does not
count as a pass.

Server shape:

```bash
rapid-mlx serve MODEL_PATH \
  --served-model-name MODEL \
  --host 127.0.0.1 --port 8800 --max-num-seqs 1 \
  --tool-call-parser hermes --reasoning-parser qwen3 \
  --enable-auto-tool-choice
```

The dense control additionally used `--no-mllm` so both arms exercised the
same text engine. The candidate selected that lane automatically.

## Performance method

Each arm was fully warmed, then received three unique-cache-miss streaming
requests through `/v1/chat/completions`. Every request had exactly 8,026 prompt
tokens, requested 256 output tokens, used temperature zero, and finished at the
length cap. TTFT is wall time to the first content delta. Decode throughput is
the remaining completion tokens divided by time from the first to last content
delta.

The deterministic prompt consisted of 420 numbered inspection records followed
by a request for a detailed 400-word engineering discussion. Only a numeric
nonce changed per run, preventing an exact prefix-cache hit while preserving
token count and workload shape.

## Performance results

| Model | TTFT runs (s) | Median TTFT | Decode runs (tok/s) | Median decode | Median E2E |
| --- | --- | ---: | --- | ---: | ---: |
| Whittle v2.1 4-bit | 17.635, 17.303, 17.280 | **17.303 s** | 16.446, 16.363, 15.934 | **16.363** | **33.026 s** |
| Dense 27B 4-bit | 24.731, 24.279, 24.259 | 24.279 s | 25.543, 25.538, 25.376 | 25.538 | 34.370 s |

Relative to dense, Whittle improved 8K TTFT by **28.7%**, regressed decode by
**35.9%**, and improved this 256-token end-to-end workload by only **3.9%**.
The crossover is unfavorable for ordinary answers: after the first token,
Whittle loses roughly 9.2 tokens/s. Longer generations therefore become slower
than dense even though prefill is faster.

As a secondary check, direct MLX-LM generation on a short arithmetic prompt
reported 16.079 tok/s and 15.738 GB peak, consistent with the service decode
result. The conversion author's CUDA smoke numbers are not used as Apple
Silicon performance evidence.

## Reproduction appendix

The ordinary prompts were sent verbatim as follows:

```text
R1: A bat and ball cost $1.10 total. The bat costs $1.00 more than the
    ball. Give the ball's cost in cents and briefly justify it.
R2: Three boxes are labeled Apples, Oranges, and Mixed, but every label is
    wrong. You may draw one fruit from one box. Which box do you draw from,
    and how do you relabel all three?
R3: A train travels 120 km at 60 km/h and returns 120 km at 40 km/h. What
    is its average speed for the whole trip? Show the decisive calculation.
R4: Find the smallest positive integer n such that n leaves remainder 1
    when divided by 2, 3, 4, 5, and 6, and is divisible by 7. Give n and a
    short verification.

C1: Write a Python function merge_intervals(items) that merges overlapping
    closed integer intervals. Return only one fenced Python block. Example:
    [(1,3),(2,6),(8,10)] -> [(1,6),(8,10)]. Do not mutate the input.
C2: Write a Python function first_unique(s) returning the first Unicode
    character that occurs exactly once, or None. Return only one fenced
    Python block. It must handle the empty string.
C3: Write a Python function topo_sort(nodes, edges) returning a deterministic
    topological order, choosing the lexicographically smallest available
    node; raise ValueError on a cycle. Return only one fenced Python block.
C4: Write a Python function json_pointer_get(doc, pointer) implementing RFC
    6901 lookup for objects and arrays, including ~0 and ~1 unescaping and
    the empty pointer. Return only one fenced Python block.

Z1: 用中文简要解释为什么蒙提霍尔问题中换门的胜率是三分之二。限四句话。
Z2: 把下面这句话翻译成自然、专业的中文，不要添加解释：The cache must
    preserve explicit operator overrides while choosing a safe automatic
    default.
Z3: 某商品先涨价20%，再降价20%。请用中文说明最终价格相对原价的变化，并给出百分比。
Z4: 请写一个恰好包含三项的编号清单，说明本地大模型服务启动失败时应先检查什么。每项不超过十五个汉字。
```

Tool requests used `tool_choice="required"`, the four function names and exact
arguments shown in the panel table, JSON Schema required fields for every
argument, and `additionalProperties=false`. Their user text was:

```text
T1: What is the weather in Tokyo in Celsius?
T2: Look up the current price for AAPL.
T3: Schedule a 30 minute meeting called Release audit at
    2026-09-02T10:30:00-07:00 with alice@example.com and bob@example.com.
T4: Search the local docs for hybrid prefix cache admission and return the
    top 3 matches.
```

The recall document was generated with the following deterministic rule:

```python
rows = []
facts = {
    37: "Project Alder's launch code is HARBOR-7319.",
    173: "The north warehouse closes every Tuesday at 18:40.",
    401: "Sample R-88 must be stored at minus 17 degrees Celsius.",
    733: "Dr. Lin's emergency extension is 6042.",
}
for i in range(800):
    rows.append(
        f"Record {i:04d}: inventory batch {10000 + i} was inspected and "
        "archived under routine policy."
    )
    if i in facts:
        rows.append(facts[i])
```

Each recall request prepended `Use only the document below`, appended one of
the four exact questions from the panel table, and requested only the target
code, time, temperature/unit, or digits. The service tokenizer reported the
exact prompt-token counts in the results table.

The performance request used the same deterministic pattern for every run:

```python
filler = " ".join(
    f"Section {i:04d} records that batch {70000+i} passed routine inspection."
    for i in range(420)
)
prompt = (
    f"Benchmark nonce {run}. Read the records, then write a detailed "
    "400-word discussion of why deterministic verification matters in "
    "engineering. Do not quote the records.\n" + filler
)
```

## Limitations

- This is one host, one deterministic sample per correctness prompt, and three
  performance repetitions. It supports a product admission decision, not a
  general leaderboard claim.
- The dense control contains an unused MTP head; MTP was disabled so generation
  remained autoregressive, but the extra tensors account for part of its
  approximately 1.13 GB larger artifact.
- The reasoning cap exposed verbosity in both models. This is intentional for a
  bounded assistant workload, but dense's three partial reasoning responses
  should not be presented as full passes.
- Tool parsing used the same explicit existing profile on both arms. The raw
  candidate repository has no Rapid alias metadata of its own.
- The source model's own notes report remaining loop and structured-output
  failures. Those claims were treated as risk context, not substituted for the
  independent panel above.

## Re-entry gate

Reconsider only a new immutable upstream revision, and require all of:

1. no elementary-reasoning regression against dense on this exact panel;
2. all four generated-code contracts pass;
3. no repetition or garbling in the four Chinese cases and an added long-form
   anti-loop sample;
4. tool JSON and 19K recall remain 4/4;
5. either decode throughput reaches parity or a clearly identified prefill-heavy
   user segment benefits enough to justify a separate experimental profile.
